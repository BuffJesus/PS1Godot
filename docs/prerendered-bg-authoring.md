# Pre-rendered background authoring

Resident Evil / FFVII-style fixed-camera scenes in PS1Godot.

## What and when to use it

The technique: the PS1 runtime renders only the player avatar (and any dynamic
actors) as live 3D. All static environment detail — walls, props, lighting,
shadows — lives in a 256×240 PNG baked from Godot's renderer. The camera is
fixed; you author one PNG per angle.

**Trade-off:** virtually unlimited visual complexity for the static environment
(bake time is seconds, not MIPS cycles), but the camera cannot move. One PNG
per camera angle; swap cameras and canvases on trigger.

**When to use:**
- Static indoor environments: taverns, dungeon corridors, office rooms
- Scenes with rich lighting/shadow detail beyond the PS1's poly budget
- Classic survival-horror navigation (tank controls + fixed cuts)

**When not to use:**
- Open outdoor areas where the horizon scrolls with the player
- Scenes with moving backgrounds (rain curtains, animated water) — those need
  runtime meshes
- Cutscene cameras driven by `PS1Cutscene` tracks (those already handle their
  own coordinate conversion)

## Scene structure

The canonical example is `godot-ps1/demo/prerendered_demo.tscn`: two rooms
(Room A, Room B) connected by a short corridor, each with a baked background
PNG and a fixed camera.

```
PrerenderedDemo (PS1Scene)
├── PS1Player
│   └── <avatar MeshInstance3D>         ← low-poly player mesh
│
├── FixedCameraA (Camera3D + PS1Camera) ← frames Room A
├── FixedCameraB (Camera3D + PS1Camera) ← frames Room B
│
├── FloorA       (PS1MeshInstance  ExportMode=CollisionOnly  Collision=Static)
├── Cube_A1      (PS1MeshInstance  ExportMode=CollisionOnly  Collision=Static)
├── Cube_A2      (PS1MeshInstance  ExportMode=CollisionOnly  Collision=Static)
├── Corridor     (PS1MeshInstance  ExportMode=CollisionOnly  Collision=Static)
├── FloorB       (PS1MeshInstance  ExportMode=CollisionOnly  Collision=Static)
├── Cube_B1      (PS1MeshInstance  ExportMode=CollisionOnly  Collision=Static)
│
├── TriggerA (PS1TriggerBox)            ← corridor→Room A boundary
├── TriggerB (PS1TriggerBox)            ← corridor→Room B boundary
│
├── background_a (PS1UICanvas  SortOrder=255)
│   └── bg_image (PS1UIElement  Type=Image  Texture=…_FixedCameraA.png)
│
└── background_b (PS1UICanvas  SortOrder=255  VisibleOnLoad=false)
    └── bg_image (PS1UIElement  Type=Image  Texture=…_FixedCameraB.png)
```

## Step-by-step authoring

### 1. Place the cameras

Add a `Camera3D` node per fixed angle. Attach `addons/ps1godot/nodes/PS1Camera.cs`
as its script. `PS1Camera` auto-wires a `PS1PixelizeEffect` compositor so the
editor preview approximates the PSX look in the viewport.

Frame the shot as you would a screenshot. In the demo:

- `FixedCameraA` is at `(0, 6, 10)` in Godot world space, tilted ~16° down
- `FixedCameraB` is at `(0, 6, -2)`, same pitch, framing the far room

The exporter reads every `Camera3D` in the scene (skipping those under
`PS1Player`, which are third-person rig offsets) and generates a Lua preamble:

```lua
-- AUTO-GENERATED by PS1Godot exporter -- DO NOT EDIT.
-- Move a camera or change FOV in Godot and re-export to update.
local _ps1_cameras = {
    ["FixedCameraA"] = { px=0, py=-1.5, pz=-2.5, rx=-0.16, ry=0, rz=0, h=257 },
    ["FixedCameraB"] = { px=0, py=-1.5, pz=0.5,  rx=-0.16, ry=0, rz=0, h=257 },
}
function Camera.LoadFromExport(name)
    local c = _ps1_cameras[name]
    if c then
        Camera.SetPosition(Vec3.new(c.px, c.py, c.pz))
        Camera.SetRotation(Vec3.new(c.rx, c.ry, c.rz))
        Camera.SetH(c.h)
    end
end
```

Your scene script calls `Camera.LoadFromExport("FixedCameraA")` — no manual
coordinate math. If you reposition a camera in the editor and re-export, the
preamble updates automatically.

### 2. Configure PS1Player

Set `PS1Player.CameraMode = FixedPreRendered` in the inspector. This is an
authoring hint; the runtime camera-follow is actually disabled by the Lua call
`Camera.SetMode("fixed")` — both are needed for the round-trip to work.

For the avatar mesh, add a child `MeshInstance3D`. Keep it low-poly; Godot's
default 64-radial `CapsuleMesh` bakes to `ArrayMesh` at hundreds of triangles.
Author a ~100–200 tri capsule instead. Assign `PS1Player.AvatarTexture` if the
mesh has a texture — this survives FBX re-imports without breaking the material
wiring.

### 3. Collision geometry with ExportMode = CollisionOnly

The scene's walls and floors must exist in Godot so:
a) they appear in the bake render, and
b) they supply runtime collision and navigation for the player.

But they must **not render** at runtime — the pre-rendered PNG replaces them.
The solution: `PS1MeshInstance` with `ExportMode = CollisionOnly`. The mesh is
invisible at PS1 runtime but still generates AABB colliders and navmesh.

For every wall/floor/prop mesh:

| Property | Value |
|----------|-------|
| `ExportMode` | `CollisionOnly` |
| `Collision` | `Static` |

For decorative props above eye-line (ceiling fixtures, hanging signs) that
cannot physically block the player, set `Collision = None` — saves BVH entries
with no gameplay cost.

`CollisionOnly` is a splashpack export flag, not a Godot visibility flag. These
meshes remain visible in the editor viewport (helpful for placement and lighting
reference) but export as collision-only entries the runtime never draws.

### 4. Navigation

For simple scenes, the exporter auto-generates navigation regions from flat
`CollisionOnly` `PS1MeshInstance` AABBs. No `PS1NavRegion` nodes needed for
rectangular rooms.

For ramps, non-rectangular outlines, or explicit multi-room portal control, add
`PS1NavRegion` nodes manually:

- `Verts`: convex polygon in local space, CCW from above (+Y). Up to 8 verts.
  Equal Y values = flat floor; three different Ys = ramp.
- `SurfaceType`: `Flat` (default), `Ramp`, or `Stairs`
- `RoomIndex`: match the `PS1Room.RoomIndex` to enable portal culling in
  multi-room scenes (leave at 0xFF for exteriors / single-room scenes)

**Portal stitching:** when two `PS1NavRegion` polygons share edge endpoints that
coincide within a small world-space epsilon, the exporter automatically connects
them with a portal. Share verts exactly at room/corridor boundaries — don't
leave a gap.

### 5. Background canvases

For each camera angle, create a `PS1UICanvas` + `PS1UIElement` pair:

**PS1UICanvas:**

| Property | Value | Notes |
|----------|-------|-------|
| `CanvasName` | e.g. `"background_a"` | Used in Lua `UI.SetVisible` |
| `SortOrder` | `255` | High = drawn first = behind. Use 200–255 for BGs. |
| `VisibleOnLoad` | `true` (initial room), `false` (others) | Only one BG visible at a time |

**PS1UIElement (child of canvas):**

| Property | Value | Notes |
|----------|-------|-------|
| `Type` | `Image` | — |
| `X / Y` | `32 / 0` | Centers a 256-wide image in the 320 px framebuffer |
| `Width / Height` | `256 / 240` | Full PS1 screen |
| `Texture` | The baked PNG | Assign after the bake step below |
| `BitDepth` | `TEX_8BIT` | Default; see VRAM notes below |

**SortOrder semantics (LIFO-inverted):**
- Lowest sortOrder = drawn last = on top (0–10: HUD elements, dialog boxes,
  full-screen fades)
- Highest sortOrder = drawn first = behind (200–255: pre-rendered backdrops)

The exporter clamps `SortOrder` to `uint8_t` (0–255). Setting 9999 in the
`.tscn` serializes as 9999 in Godot but becomes 255 in the splashpack — correct,
but set 255 directly to avoid confusion.

**BitDepth options for backgrounds:**

| Value | VRAM cost (256×240) | Use when |
|-------|---------------------|----------|
| `TEX_8BIT` (1) | ~61 KB (pixels) + 512 B (CLUT) | Most hand-authored environments; the 256-color palette is usually sufficient |
| `TEX_16BIT` (2) | ~120 KB | Photo-quality sources, gradients, or when palette banding is visible |

Each 16bpp background takes ~12% of PS1 VRAM (1 MB total). Budget two BG images
per scene maximum if you also have character and world textures resident.

### 6. PS1Scene settings

On the root `PS1Scene` node:
- `BackgroundColorEnabled = true` — sets the PS1 clear color so the framebuffer
  doesn't show garbage on the first frame before the BG canvas draws
- `SceneLuaFile` — point to your scene Lua script

## Bake workflow

Select a `Camera3D` in the scene tree, then **Tools → Bake Background**.

`BackgroundBaker` runs the following pipeline:

1. **Auto-bakes Vertex Lighting + AO** for every `Light3D` and `PS1MeshInstance`
   pair in the scene. This replaces the three-step manual flow (Bake Vertex
   Lighting → Bake AO → Bake Background). If you've hand-painted `BakedColors`
   and don't want them overwritten, remove the scene's `Light3D` nodes before
   running the background bake, or use the standalone bake actions.

2. **Stamps `BakedColors` into mesh `COLOR` arrays** temporarily. Godot's
   renderer sees vertex colors only through the mesh `COLOR` attribute; the
   `PS1MeshInstance.BakedColors` property is a per-instance override invisible
   to Godot's pipeline. The baker swaps in temporary `ArrayMesh` copies with
   `BakedColors` stamped into the `COLOR` slot, restoring the originals after
   the capture.

3. **Mutes the PSX preview shader:**
   - `modulate_scale → 1.0` (removes the 2× PSYQo vertex-color convention)
   - `preview_quantize_bits → 0` (disables 5-bit channel quantize)
   - `preview_dither_enabled → false` (disables Bayer dither)
   
   The bake captures Godot's native shading — the pre-rendered BG should look
   *better* than what the PS1 can render live. The PSX-look effects should not
   bake into the texture.

4. **Renders a `SubViewport`** at 256×240 from the source camera's exact
   transform and FOV, sharing the scene's `World3D`.

5. **Saves to** `res://assets/backgrounds/<scene>_<camera>.png`.

6. **Restores** all shader state and mesh swaps.

7. **Triggers `EditorFilesystem.Scan()`** so the new asset is immediately
   importable without a manual reimport.

After the bake, assign the saved PNG to the matching `PS1UIElement.Texture`.

**Re-baking:** just run Bake Background again. The baker overwrites the previous
PNG. Since the bake also auto-runs lighting/AO, the background stays in sync
with scene lighting changes.

**Blank image:** the camera doesn't see any geometry. Check that the camera
frustum intersects the mesh nodes, and that the meshes are visible in the editor
(Godot visibility, not the `ExportMode` flag — `CollisionOnly` is runtime-only).

## Lua runtime control

Scene script: `godot-ps1/lua/demo/prerendered_demo.lua`.

### Camera.LoadFromExport (recommended)

The exporter auto-generates a `Camera.LoadFromExport(name)` helper. Your scene
script just names the camera:

```lua
function onSceneCreationEnd()
    Controls.SetEnabled(true)

    -- Start in Room A: lock the camera to FixedCameraA's pose, show its BG.
    Camera.LoadFromExport("FixedCameraA")
    Camera.SetMode("fixed")              -- disables the player-follow rig

    UI.SetVisible("background_a", true)
    UI.SetVisible("background_b", false)
end
```

`Camera.SetMode("fixed")` is the Lua call that activates `FixedPreRendered`
mode at runtime. The `PS1Player.CameraMode` inspector field is the authoring
annotation; `Camera.SetMode` is what the runtime actually reads.

### Trigger-driven camera cuts

`onTriggerEnter(triggerIndex)` fires when the player's AABB enters a
`PS1TriggerBox`. Indices are assigned in **scene-walk (tree) order** — the
trigger's position in the inspector hierarchy determines its index, not its
spatial position.

```lua
-- TriggerA = index 0 (first PS1TriggerBox in the tree)
-- TriggerB = index 1 (second PS1TriggerBox in the tree)
function onTriggerEnter(triggerIndex)
    if triggerIndex == 0 then
        Camera.LoadFromExport("FixedCameraA")
        UI.SetVisible("background_a", true)
        UI.SetVisible("background_b", false)
    elseif triggerIndex == 1 then
        Camera.LoadFromExport("FixedCameraB")
        UI.SetVisible("background_a", false)
        UI.SetVisible("background_b", true)
    end
end
```

`UI.SetVisible` matches on `PS1UICanvas.CanvasName` — must be an exact string
match.

### Manual coordinates (legacy)

If you need a pose not driven by a `Camera3D` node, use the raw API. All
coordinates are **PSX runtime space**, not Godot world space.

**Position conversion** (default `GteScaling = 4`):

| Godot axis | → PSX runtime |
|------------|---------------|
| `x_godot` | `x_psx = x_godot / 4` |
| `y_godot` | `y_psx = −y_godot / 4` |
| `z_godot` | `z_psx = −z_godot / 4` |

Y and Z both flip sign. With `GteScaling = 4`, divide by 4. Example: Godot
position `(0, 6, 10)` → PSX `(0, −1.5, −2.5)`.

**Rotation:** angles in units of π (full circle = 2.0). Pitch is the X
component; **negative pitch = look down**. The `Camera.LoadFromExport` helper
handles the Godot→PSX angle conversion automatically — the manual path is only
needed when the camera pose is computed dynamically in Lua.

```lua
-- Manual equivalent of Camera.LoadFromExport("FixedCameraA"):
Camera.SetPosition(Vec3.new(0, -1.5, -2.5))
Camera.SetRotation(Vec3.new(-0.16, 0.0, 0.0))
Camera.SetH(257)   -- from FOV 50° → H = 120 / tan(25°) ≈ 257
```

## Common pitfalls

**Background looks posterized (CLUT banding)**  
Default `BitDepth = TEX_8BIT` = 256-color palette quantization. Switch to
`TEX_16BIT` for photorealistic or gradient-heavy backgrounds. Costs ~2× VRAM
per BG image (~120 KB vs ~61 KB).

**Bake PNG is overexposed / washed out**  
The PSYQo vertex-color convention stores "neutral" at 0.5 (shader doubles it to
1.0). If `BakedColors` values are above 0.5 and the PSX preview shader was
somehow active during the bake, vertex colors get doubled. Confirm the baker's
Output panel shows the shader-mute log line:
`BG baker: muting PSX shader during bake (modulate ... → 1, ...)`.
If it doesn't appear, the editor is running an old plugin DLL — close and reopen
Godot.

**FBX textures missing from the bake**  
Godot's FBX importer may attach `StandardMaterial3D` albedo textures in ways
the `ps1_default` shader doesn't read. If the bake is uniformly grey, manually
assign the texture to the `MeshInstance3D.material_override`'s `albedo_tex`
shader parameter, or set `PS1Player.AvatarTexture` for the player mesh.

**Camera still follows the player at runtime**  
Two things are required: (1) `PS1Player.CameraMode = FixedPreRendered` in the
inspector, and (2) `Camera.SetMode("fixed")` called in Lua at scene start. The
inspector field alone is not enough — `Camera.SetMode` is what the runtime
executes.

**`Camera.LoadFromExport` returns nil / does nothing**  
The preamble is only generated when the scene has at least one `Camera3D` (not
under `PS1Player`). Check that the camera nodes are direct or indirect children
of the scene root, not nested under a `PS1Player`. Also check that the name
passed to `LoadFromExport` exactly matches the Godot node name (case-sensitive).

**Room transition trigger never fires**  
Verify `PS1TriggerBox.ScriptFile` points to the correct `.lua` file. Add
`Debug.Log("trigger " .. triggerIndex)` at the top of `onTriggerEnter` to
confirm the trigger is reaching Lua. If indices seem wrong, recount tree
order — indices are 0-based and assigned in scene-walk order, not by spatial
position.

**CollisionOnly meshes visible at PS1 runtime**  
Double-check the `ExportMode` property on each `PS1MeshInstance` — it should be
`CollisionOnly`, not `MergeStatic` or `KeepSeparate`. The `Visible` toggle in
Godot's inspector does not affect runtime visibility; only `ExportMode` does.

**SortOrder above 255**  
`PS1UICanvas.SortOrder` is a `uint8_t` in the splashpack (range 0–255). The
inspector allows higher values but the exporter clamps to 255. Set it directly
to 255 rather than 9999 to keep the `.tscn` readable.

**Two BG canvases both start visible**  
Set `VisibleOnLoad = false` on every canvas except the one for the player's
starting room. The runtime's `UI.SetVisible` toggles them at camera cut time;
having two visible simultaneously means both BGs draw (one on top of the other).

**Per-mesh lighting bake not applied to PNG**  
The background bake auto-runs Vertex Lighting + AO if the scene has any
`Light3D`. If meshes still appear white/flat in the PNG, confirm `Light3D` nodes
are present and enabled in the scene. The bake prints the number of meshes baked
to the Output panel — `0 mesh(es)` means the baker found no lights.
